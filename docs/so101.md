# SO101 Left Arm

Configs for a single SO101 arm with a top and a wrist camera, trained on `hungho77/so101-left-arm-multitask`
(11 tasks, 30 fps). The actions are absolute joint positions: the 5 arm joints are trained as deltas and the gripper
stays absolute.

| Config | Model |
|---|---|
| `pi05_so101_left` | π0.5 with metadata prompting, real-time chunking and knowledge insulation |
| `value_so101_left` | RECAP value function |
| `pi05_so101_left_recap` | Advantage-conditioned policy with memory and subgoal images |
| `subtask_so101_left` | High-level policy (needs subtask annotations) |

All configs are set up for PyTorch training (see [pytorch_training.md](pytorch_training.md)).

## Dataset

The pinned LeRobot version reads datasets in the v2.1 format. Use a v2.1 copy of the dataset, placed (or linked) at
`$HF_LEROBOT_HOME/hungho77/so101-left-arm-multitask`. Its `meta/info.json` must contain the keys
`observation.images.top`, `observation.images.wrist`, `observation.state` and `action`. If the keys differ, change the
repack transform in `LeRobotSO101DataConfig`.

## Steps

```bash
# Setup.
GIT_LFS_SKIP_SMUDGE=1 uv sync
cp -r ./src/openpi/models_pytorch/transformers_replace/* .venv/lib/python3.11/site-packages/transformers/

# pi05_base in PyTorch.
uv run python -c "import openpi.shared.download as d; print(d.maybe_download('gs://openpi-assets/checkpoints/pi05_base'))"
uv run examples/convert_jax_model_to_pytorch.py --config_name pi05_libero \
    --checkpoint_dir ~/.cache/openpi/openpi-assets/checkpoints/pi05_base \
    --output_path ./checkpoints/pi05_base_pytorch

# Normalization statistics and episode speeds.
uv run scripts/compute_norm_stats.py --config-name pi05_so101_left
uv run scripts/compute_episode_metadata.py --repo-id hungho77/so101-left-arm-multitask --speed-bin-size 50
```

`compute_episode_metadata.py` prints the speed distribution. `target_speed` is set to the 15th percentile of the episode
lengths (289 steps, rounded to 300), which prompts the policy for fast execution at inference. The dataset has no
quality or mistake labels, so these fields are left out of the prompt.

Short trial run on 2 MIG instances:

```bash
ALL_DEVICES=$CUDA_VISIBLE_DEVICES uv run torchrun --standalone --nnodes=1 --nproc_per_node=2 --no-python \
    scripts/per_device.sh python scripts/train_pytorch.py pi05_so101_left --exp_name trial \
    --num_train_steps 20 --overwrite
```

Then run the full training without `--num_train_steps`. For RECAP, run `value_so101_left`, then
`scripts/compute_advantages.py` with `--output assets/value_so101_left/advantages.npz`, then `pi05_so101_left_recap`
(see [recap.md](recap.md)). Run `compute_norm_stats.py` for each config first.

## Open-loop evaluation

`scripts/eval_open_loop.py` replays recorded episodes: every `--action-horizon` steps the policy predicts a chunk from
the recorded observation, and the first `--action-horizon` actions are compared with the recorded ones (unnormalized).
It writes the per-episode errors and the error of a baseline that holds the action at the start of each chunk to
`results.json`, and the predictions and plots per episode.

By default the prompt contains the speed of the evaluated episode (`--speed episode`). With the fast `target_speed` of
the config (`--speed target`), the predictions run ahead of slower recorded episodes, so the open-loop error is higher
even if the policy works well.

```bash
uv run scripts/eval_open_loop.py --config-name pi05_so101_left \
    --checkpoint-dir checkpoints/pi05_so101_left/so101_v1/30000 --output-dir eval/so101_v1 \
    --episodes 0 50 100 150 200 251 301 351 401 451 501 --action-horizon 16 --steps 400
```
